# 1.3 — IPv6 : notation, préfixes et voisinage

> Fiche du chapitre 1.3 du module [01 — Réseau : les bases](README.md).
> Plan complet : [README.md#plan](README.md#plan).

## Objectifs d'apprentissage

1. **Écrire et lire une adresse IPv6** sans se tromper sur la compression `::`.
2. **Découper un `/64`** et comprendre pourquoi c'est la taille standard d'un LAN.
3. **Distinguer les types d'adresses** : lien local, globale, ULA, multicast.
4. **Reconnaître le voisinage IPv6** (NS/NA) là où IPv4 utilise ARP, et SLAAC là où IPv4 utilise
   DHCP.
5. **Filtrer IPv6 dans Wireshark** et expliquer pourquoi `ping` échoue alors que la pile est
   active.

## 1. Notation

Une adresse IPv6 fait 128 bits, écrits en huit groupes de 16 bits en hexadécimal :

```text
2001:0db8:0001:0000:0000:0000:0000:0010
```

Trois règles de simplification, dans cet ordre :

1. **les zéros de tête** de chaque groupe disparaissent : `0db8` → `db8` ;
2. **une seule** suite de groupes nuls consécutifs peut être remplacée par `::` ;
3. la forme canonique s'écrit en minuscules, avec `::` le plus à gauche possible.

```text
2001:db8:1::10
```

`::` ne peut apparaître qu'une fois : sinon `2001::1::2` serait ambigu. Une adresse comme
`::1` (boucle locale) et `::` (non spécifiée) restent valides.

Le préfixe suit la même logique qu'IPv4 : `/64` signifie que les 64 premiers bits identifient le
réseau, et les 64 derniers l'interface.

## 2. Pourquoi /64 partout

| Taille | Adresses | Usage réel |
| --- | --- | --- |
| `/64` | 2^64 | un LAN standard, une seule par segment |
| `/56` | 2^56 | un site client chez un FAI (256 LAN) |
| `/48` | 2^48 | un site entier (65 536 LAN) |
| `/128` | 1 | une seule adresse (loopback, route) |

Un `/64` contient 18 milliards de milliards d'adresses : le balayage exhaustif n'existe plus, ce
qui change la donne pour l'audit comme pour l'attaque. En contrepartie, la taille fixe simplifie
tout : SLAAC, autoconfiguration, et les tables de routage.

## 3. Types d'adresses

| Préfixe | Type | Équivalent IPv4 | Remarque |
| --- | --- | --- | --- |
| `::1/128` | boucle locale | `127.0.0.1` | |
| `::/128` | non spécifiée | `0.0.0.0` | source d'un RS au démarrage |
| `fe80::/10` | lien local | `169.254.0.0/16` | **toujours présente**, obligatoire pour NDP |
| `2000::/3` | globale | adresse publique | routée sur Internet |
| `fc00::/7` | ULA (privée) | RFC 1918 | `fd00::/8` en pratique |
| `ff00::/8` | multicast | — | pas de diffusion en IPv6 |
| `ff02::1` | tous les nœuds | — | multicast lien local |
| `ff02::2` | tous les routeurs | — | |
| `ff02::1:ffXX:XXXX` | sollicitation de nœud | — | dérivée de l'adresse visée |

**IPv6 n'a pas de diffusion.** Là où IPv4 envoie à `255.255.255.255`, IPv6 utilise un groupe
multicast. Conséquence pratique : un scan qui compte sur le broadcast IPv4 ne trouve rien.

## 4. Voisinage : NDP remplace ARP

| Besoin | IPv4 | IPv6 |
| --- | --- | --- |
| Trouver la MAC d'une IP | ARP request/reply | **NS** (type 135) / **NA** (type 136) |
| Découvrir la passerelle | DHCP ou config manuelle | **RS** (133) / **RA** (134) |
| S'autoconfigurer | DHCP | **SLAAC** à partir du RA |

Un RA transporte un préfixe (`/64`), une durée de vie et éventuellement l'indication « utilise
DHCPv6 ». C'est ainsi qu'une machine obtient une adresse globale sans serveur DHCP.

Capture de laboratoire, générée pour l'exercice (deux hôtes `2001:db8:1::10` et `::1`, MAC
`aa:00:…:01` et `aa:00:…:fe`) :

```bash
tshark -r ipv6-lab.pcap -T fields -e frame.number -e ipv6.src -e ipv6.dst -e ipv6.hlim \
       -e icmpv6.type -e icmpv6.nd.ns.target_address
```

```text
1       2001:db8:1::10  ff02::1:ff00:1  255     135     2001:db8:1::1
2       2001:db8:1::1   2001:db8:1::10  255     136
3       2001:db8:1::10  2001:db8:1::1   64      128
4       2001:db8:1::1   2001:db8:1::10  64      129
5       fe80::1 ff02::1 255     134
```

Lecture :

- **trame 1** : NS vers l'adresse de sollicitation de nœud `ff02::1:ff00:1`, qui correspond à
  `2001:db8:1::1`. C'est l'ARP d'IPv6, en multicast ciblé.
- **trame 2** : NA en retour. Le drapeau `S` (solicited) indique une réponse à une sollicitation.
- **trames 3 et 4** : echo request (128) / echo reply (129), `hlim 64`.
- **trame 5** : RA depuis `fe80::1` vers `ff02::1`, avec un préfixe `/64` : c'est SLAAC.

Les paquets NDP ont `hlim = 255`, une valeur vérifiée par les routeurs pour empêcher l'envoi
depuis un autre segment. Un NS avec un TTL plus faible est suspect.

## 5. Vérifier sur la machine

```bash
ip -6 addr
ip -6 route
```

Sur un système où IPv6 est désactivé, les deux commandes ne renvoient **rien** :

```text
```

Le diagnostic tient en une ligne :

```bash
cat /proc/sys/net/ipv6/conf/all/disable_ipv6
```

```text
1
```

`1` signifie désactivé. Beaucoup d'images de conteneurs et de machines endurcies le font, ce qui
explique un `ping6` muet alors que la pile réseau fonctionne parfaitement.

## 6. En-tête simplifié

| Champ | IPv4 | IPv6 |
| --- | --- | --- |
| Taille d'en-tête | 20 à 60 octets | **40 octets fixes** |
| Somme de contrôle | oui | **non** (déléguée aux couches basses) |
| Fragmentation | routeurs et source | **source uniquement** |
| Options | dans l'en-tête | extensions chaînées |
| TTL | 8 bits | *Hop limit*, même rôle |

Trois conséquences :

- plus de checksum d'en-tête : rien à recalculer à chaque saut ;
- la fragmentation en route disparaît : c'est **PMTUD** (Path MTU Discovery) qui doit fonctionner,
  donc ICMPv6 type 2 (« packet too big ») ne doit jamais être filtré ;
- `hlim` joue exactement le rôle du TTL, y compris pour `traceroute6`.

## 7. Filtres Wireshark

| Objectif | Filtre |
| --- | --- |
| Un hôte | `ipv6.addr == 2001:db8:1::10` |
| Un préfixe | `ipv6.addr == 2001:db8:1::/64` |
| NDP | `icmpv6.type == 135 \|\| icmpv6.type == 136` |
| SLAAC | `icmpv6.type == 134` |
| Echo | `icmpv6.type == 128 \|\| icmpv6.type == 129` |
| Lien local | `ipv6.src >= fe80:: && ipv6.src < fec0::` |
| Multicast | `ipv6.dst == ff02::1` |

En capture, `tcpdump 'ip6'` ou `'icmp6'` ; en affichage, `ipv6` seul suffit.

## 8. Pièges

| Symptôme | Cause |
| --- | --- |
| `ping6 fe80::1` échoue | adresse lien locale sans zone : `ping6 fe80::1%eth0` |
| Rien dans `ip -6 addr` | IPv6 désactivé (`disable_ipv6 = 1`) |
| `curl` passe par IPv4 alors qu'IPv6 existe | préférence de pile (`/etc/gai.conf`), ou AAAA absent |
| IPv6 « lent » | PMTUD cassé par un pare-feu qui jette ICMPv6 |
| Adresse qui change toutes les 24 h | extensions de confidentialité (RFC 8981) : normal, pas une attaque |
| Scan IPv4 ne trouve aucun hôte IPv6 | pas de diffusion en IPv6 : il faut du multicast ou de l'énumération DNS |

## À retenir

- `::` une seule fois, minuscules, `/64` pour un LAN.
- Pas de diffusion : multicast, NS/NA, RS/RA.
- `fe80::/10` est toujours là et sert à NDP, même sans adresse globale.
- ICMPv6 n'est pas optionnel : le filtrer casse la fragmentation et le voisinage.
- `disable_ipv6 = 1` explique la plupart des « IPv6 ne marche pas » en conteneur.
